## Findings recorded, not fixed

This change is a re-baseline: no bridge source changed. These are recorded for
the discovery loop, each in the evidence file named:

- **`interrupt` is the real cancel path.** Iteration 1 aimed the interrupt
  scenario at `control_cancel_request`, which at the pin only denies a pending
  permission ask (`sdk_mode.rs` L732–L742). Any future interrupt coverage test
  must target inbound `control_request`/`interrupt` (L840–L843).
- **The bridge emits four event names absent from the pin** — `model.updated`,
  `permission.asked`, `permission.replied`, plus `server.connected` which is
  pinned only by the live capture. Same phantom class as a route, on the event
  side (`opencode-tui-features.md`).
- **`GET /api/fs/read/*` is a literal wildcard.** The pin spells it with `*`,
  not `{param}`, so the bridge answers the literal path `200` and 404s every
  real file path. The row is truthful as spelled; the unusability is recorded,
  not status-flipped (`route-classification.md`).
- **Zero rows land at `unhandled`.** The proposal expected "a handful that
  dispatch genuinely rejects"; measured as spelled across all 142 operations,
  the bridge rejects none. `unhandled` is left empty rather than forced.
