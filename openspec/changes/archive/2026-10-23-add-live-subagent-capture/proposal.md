# Proposal

## Why

`bridge/test/fixtures/maki-subagent.jsonl` was authored from a reading of
pinned Maki `sdk_mode.rs` v0.6.4 and never captured from a live subagent turn
(`provenance.json`: `kind: authored`). Its golden is generated by projecting
that same fixture, so the fixture and the golden agree no matter what Maki
actually does — no future run can contradict the assumption. `subagent-nesting`
carries `caveat: contract-only` for exactly this reason, and the caveat can
only be removed by observing a real turn.

Everything needed to observe one is already in place on this host: the gateway
is connected over mTLS, the `maki-synthetic` provider profile is registered
with its credential bound to a single endpoint, and the `maki-agent:local`
image is present — the same three preconditions the archived live smoke
recorded. The archived capture harness
(`openspec/changes/archive/2026-10-21-add-opencode-tui-bridge/evidence/harness/`)
is the recipe.

## What Changes

- Run one real Maki session inside the OpenShell sandbox through the existing
  `maki-synthetic` profile with `-m
  synthetic/hf:deepseek-ai/DeepSeek-V4.1-Flash-1017`, prompted so the model
  exercises the `Task` subagent tool, and commit the child's stdout as
  `bridge/test/fixtures/maki-subagent-live.jsonl` with a `provenance.json`
  entry of `captured`.
- Compare the captured `parent_tool_use_id` shape against the authored
  fixture. If it agrees, drop `caveat: contract-only` from the
  `subagent-nesting` row — the shape is then observed, not inferred. If it
  disagrees, regenerate the golden from the real capture and record the
  difference as a discovery finding; a disagreement is the entire reason this
  change exists.
- Redaction-scan the new capture with the same rule the archived evidence
  used, so no credential-shaped value lands in a committed fixture.
- Record two findings this change deliberately does not fix (see below), so
  their cost is stated rather than rediscovered.

No bridge source changes. `bridge/src/**` is untouched; the capture runs Maki
through `openshell sandbox exec`, not through the bridge.

## Capabilities

### New Capabilities

(none — this change replaces inferred evidence with observed evidence; it
introduces no new bridge behavior)

### Modified Capabilities

- `opencode-tui-bridge`: the "Render subagent-flagged frames in the session
  transcript" requirement gains a scenario committing to confirm the
  `parent_tool_use_id` wire shape against a live capture rather than a
  source-derived fixture.

## Out of scope, with reasons

- **Enabling streaming in the bridge.** The shipped child invocation is
  `maki -p --input-format stream-json --output-format stream-json` plus trust
  and model flags (`bridge/src/maki.ts`); it never passes
  `--include-partial-messages`, and pinned `sdk_mode.rs` gates every
  `stream_event` emission behind that flag. So the `stream-deltas` path cannot
  occur through the bridge as shipped. Adding the flag changes what the TUI
  sees in production — its own spec delta, its own risk review — and is not a
  capture.
- **Capturing a streaming turn.** The archived `e2e-note.md` recorded that the
  model in use then never streams. That is a property of that model, not of
  the provider or the network — naming a different model on the already
  registered profile needs no new credential and no new egress rule. It is
  still a different operation from this one, so `add-live-stream-deltas` owns
  the streaming observation and `maki-stream.jsonl` stays `authored` here.
- **Capturing a real `api_retry`.** Pinned `sdk_mode.rs` emits it from
  `AgentEvent::Retry`, which only a genuine provider failure raises and which
  cannot be requested. `maki-retry.jsonl` stays `mixed`.

## Impact

- `bridge/test/fixtures/maki-subagent-live.jsonl` — new captured fixture.
- `bridge/test/fixtures/provenance.json` — one new entry.
- `bridge/compat/statuses.json` — `subagent-nesting` loses its `caveat` field
  on confirmation, or keeps it with a recorded disagreement.
- `bridge/test/golden/` — regenerated only if the capture contradicts.
- `docs/compatibility.md` — regenerated by `make compat`.
- Evidence under this change's `evidence/`: the capture note, the shape
  comparison, the redaction scan.
- Security surface: unchanged. The run uses the existing `maki-synthetic`
  profile's single host-and-port rule, adds no endpoint, no `tls: skip`, no
  wildcard, no `access: full`; the credential reaches the proxy as a profile
  binding and the sandbox only ever sees the opaque stand-in it substitutes;
  the invocation passes no `--env` value, runs as the non-root sandbox user,
  adds no bind mount, and performs no authentication inside the sandbox.
